# 工程标准化与验收边界

目标是业务页面使用真实持久化数据，把可调业务限制集中为命名策略，并用实际故障及负载验证可用性。
样式尺寸、时间单位换算、算法必需的数值不等同于需要接口读取的业务数据。

| 领域 | 当前数据或策略来源 | 验证方式 |
|---|---|---|
| 商品、库存、订单、卖家评价 | PostgreSQL；页面读取业务 API，不回退到演示记录 | 商品、订单、角色集成与完整 Alpha 浏览器交易流程 |
| 汇率及估值 | Coinbase 快照、数据库一小时缓存；缺失时不给固定汇率 | 汇率集成与跨币种精度、排序回归 |
| 分页、购物车、收藏批次限制 | 后端及前端命名策略，OpenAPI 声明 | 三方契约测试；真实数据库边界用例 |
| 连接池、事务与请求接纳 | `database-policy.ts`、`transaction-policy.ts`、`request-policy.ts` | 数据库中断、超额拒绝、断开请求及并发业务集成 |
| 可写就绪与数据库入口 | PostgreSQL 恢复／只读状态，两个固定代理先检查主库资格 | 真实只读连接回归；双代理故障、原键回放与完整订单核对 |
| 登录节流与到期处理 | 数据库共享计数、认证与订单到期策略 | 多实例节流及订单到期集成 |
| 会话轮换及跨入口撤销 | 真实密码校验、PostgreSQL 会话状态与认证策略 | 双 HTTP 监听器实际登录／轮换／注销；七项认证集成通过，尚非持续容量 |
| 认证混合负载 | 32 个真实密码账户、真实会话轮换与跨入口审计 | 功能集成通过；两个独立 API 的持续混合容量仍待验收 |
| 容量计时与环境预检 | 命名 60 秒预检／250 毫秒采样，系统墙钟与单调时钟实测 | 81 项后端单元；真实预检在资源准备前拦截 1218 毫秒偏移，测量期间门禁仍保留 |
| 结果未知的交易 | 发起账户的原请求和幂等键；服务端校验并经过同步提交屏障 | 账号切换、迟到响应及全部备库停止后的原键回放 |
| 收藏数量 | API 确认的公开商品，不按本地 ID 数量伪造 | 不存在 ID 不计数；共享请求、两批并发及取消回归 |
| 订单刷新 | `frontend/src/lib/refresh-policy.ts`；只读请求串行、合并主动刷新 | 164 项前端测试；真实慢订单响应超过轮询周期仍只读取一次 |

数字商品没有 `DigitalInventory` 行表示当前契约中的无限供应模式；有限供应商品有实际库存行。
这是数据库表示方式，不是接口失败后的演示库存兜底。详情与检索的两类库存表示已有一致性回归。
测试 fixture 和开发种子数据仅供独立测试或显式本机开发使用，不能充当接口失败后的产品数据。

## 可用性及容量证据

确认的负载目标保持为 1000 用户、500 请求/秒、至少两个 API；数据库目标为已确认订单零丢失、
60 秒内恢复写入，全部备库丢失时暂停成功写入确认。实测报告、退出码及资源清理回执见
[容量验收](CAPACITY.md)和[数据库 HA 验收](../infra/HA.md)。

目前 500 请求/秒的本机主库及全部备库故障矩阵通过，每 API 的通过配置是池 10；
默认池 5 没有通过此前的 API 故障矩阵。十分钟单入口实现的首次复测失败，会话到期与
系统时间跳变调查已记录；统一会话 fixture 并新增时钟门禁后，同负载复测通过：
300000 请求全完成，零错误和丢弃，15000 笔订单核对，该轮最大时钟偏差 0.907 毫秒。
正常主库切换、仲裁多数丢失、主库到仲裁的独立网络隔离通过；实际 HA 子进程冻结时的
旧主库隔离门禁失败，不能用原 API 已恢复写入或订单暂未丢失来替代该门禁。
后续补充默认必需 watchdog、半租约超时与原生环境覆盖拒绝；真实 Patroni 的无设备
拒绝激活验收及本机诊断回归通过，实际设备复位与物理隔离仍待独立环境验证。

本机双 TCP 入口专项故障及完整常规 HA 验收已通过，双入口十分钟混合写入及 API 故障容量复测也已通过：
1000 用户、300000 请求全部完成，最终错误及丢弃为零，15000 笔订单核对；
一次 502 使用原键恢复。2401 次采样均保持两条 streaming、至少一条同步备库，
时钟门禁及资源清理通过。先前单入口容量报告仍保留其原有范围。

整体目标尚未完成：需要补齐经过真实故障验证的 watchdog 或外部 fencing、HTTP 入口冗余、
独立故障域部署、持续负载下的代理故障，以及包含密码登录、会话轮换和订单到期的混合负载。
本机同宿主机容器和短时资源观测不证明生产环境的高可用或不存在内存泄漏。
