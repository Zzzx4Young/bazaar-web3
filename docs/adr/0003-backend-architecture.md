# ADR-0003 — 前后端分离的模块化单体后端

状态：已接受架构方向与技术主路线。记录日期：2026-09-09；2026-09-11 V1 骨架已实现，版本与运行验证见[报告](../backend-validation-report.md)，业务模块待实施。

## 背景

在内部 Alpha 业务基线确定后，项目负责人提出用户增长、并发、对象存储、长期维护及 Web3 集成需求。用户明确确认独立模块化单体后端，并认可 TypeScript＋NestJS/Fastify＋PostgreSQL 技术路线；随后用户明确回复“选择Prisma”，ORM 方向已确定。

## 已确认决定

- 前后端分离：Next.js 负责前端，独立后端承载业务 API。
- 后端采用模块化单体；账户、商品、订单、交付等不拆成独立微服务。
- 技术主路线为 TypeScript、NestJS、Fastify HTTP 适配器、PostgreSQL。具体版本与兼容性尚未锁定。
- 按账户权限、商品、订单库存、交付异常、结算、媒体、审计划分设计职责；内部调用与事务方案见架构草案，不视为接口已定稿。
- 当前只实施内部账户与模拟结算。钱包关联、链上结算、事件同步和对账设计扩展边界，不启动钱包或合约开发。
- 2026-09-09 用户选择 Prisma；TypeORM 保留为比较记录，不作为并行实施方案。Prisma 具体版本、迁移与关键事务验证尚未完成，选择不代表性能或兼容性已验收。

## 备选与取舍

| 方案 | 取舍 |
|---|---|
| Next.js 一体化服务端 | 内测部署简单，但前后端发布耦合；未选为长期主方案 |
| 独立模块化单体（已选） | 便于职责分离、团队协作与独立扩容；增加服务维护和联调成本 |
| 微服务 | 当前缺少独立团队或扩容证据，会增加跨服务事务与运维复杂度；暂不采用 |

此选择不保证特定并发容量，也不消除数据库事务、权限、连接管理和未来链同步的一致性风险。容量与可靠性需依据负载目标及压测验证。
