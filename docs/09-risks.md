# 09. 风险清单

> 所有风险按 **可能性 × 影响** 排序,P0 = 立即关注,P1 = 重要,P2 = 持续关注。

## 1. 监管 / 合规风险(P0)

### 1.1 主要辖区禁止加密支付

**风险**: 某个目标司法管辖区(已规划的)突然禁止加密支付,平台被迫下架。

**影响**: 失去一个主要市场,直接损失 30-50% 收入。

**缓解**:
- 多辖区分散风险(不要单押)
- 监控监管动态(加入监管预警服务)
- 设计可分区域的关闭开关
- 法律预算保留应急

### 1.2 中国大陆用户绕过屏蔽

**风险**: 通过 VPN 绕过 IP 屏蔽,平台无 KYC 大陆身份证。

**影响**: 法律连带(《刑法》285 条);一旦发现,封号+退余额。

**缓解**:
- KYC 必须
- 严格协议禁止(法律效力)
- 设备指纹(后续)
- 大陆身份证 / 手机号直接拒绝

### 1.3 牌照申请被拒

**风险**: 申请 MiCA / MAS PSA 被拒,无法在欧盟 / 新加坡运营。

**影响**: 失去主要目标市场。

**缓解**:
- 提前与监管沟通
- 准备多个备选辖区(瑞士、英国、澳大利亚)
- 申请时寻求当地律所深度参与

### 1.4 OFAC / 制裁名单命中

**风险**: 平台未及时更新制裁名单,服务了被制裁用户。

**影响**: 罚款 + 刑事风险(美国)。

**缓解**:
- 每日自动更新制裁名单
- 注册时 + 大额交易时复核
- 与 Chainalysis / Elliptic 合作

## 2. 技术风险(P0)

### 2.1 智能合约漏洞

**风险**: escrow 合约被攻击,用户资金损失。

**影响**: **灾难性** — 一次性损失可能数百万美元 + 声誉损失。

**缓解**:
- **上线前**: 2 家独立审计(OpenZeppelin + Trail of Bits / Spearbit)
- **上线后**: Bug Bounty(Immunefi,最高 $100K)
- **运行时**: Timelock + 多签 + Pause 机制
- **保险**: 后续阶段考虑 Nexus Mutual 等
- **可升级**: UUPS Proxy + Timelock(可修复漏洞)

**这是最致命的风险**。

### 2.2 私钥泄露

**风险**: 平台管理钱包(运营钱包)私钥泄露。

**影响**: 平台资金损失 + 用户损失(若涉及 escrow)。

**缓解**:
- 多签(Safe{Wallet} 3/5)
- 硬件钱包
- 热钱包限额($100K)
- 操作审计
- 团队成员不单独持有私钥

### 2.3 私钥管理(用户)

**风险**: 用户私钥丢失 / 钓鱼,无法恢复。

**影响**: 用户资金永久损失,平台声誉受损。

**缓解**:
- **平台不持有用户私钥**(明确告知)
- 推动账户抽象(ERC-4337)— 社交恢复
- 安全教育(用户文档)
- 钓鱼警告

### 2.4 链上重组 / 51% 攻击

**风险**: 链上区块重组(尤其小链),escrow 交易被回滚。

**影响**: 支付状态错乱。

**缓解**:
- **等足够确认数**(12+ 区块,约 3 分钟)
- 优先使用 L1(Ethereum)
- 接受 L2 重组风险(Optimistic Rollup 7 天最终性)

### 2.5 跨链桥风险(未来)

**风险**: Phase 3 跨链桥被攻击。

**影响**: 灾难(历史上 Wormhole / Ronin 都损失过亿)。

**缓解**:
- **MVP 不做跨链桥**
- 真要做,用经过审计的桥(Wormhole 2.0? LayerZero?)
- 桥额度限制
- 监控桥 TVL

### 2.6 数据库泄露

**风险**: PostgreSQL 泄露,用户 PII 暴露。

**影响**: 违反 GDPR,罚款 + 声誉损失。

**缓解**:
- 加密 at rest(AWS RDS)
- 加密 in transit(TLS 1.3)
- 最小权限(每个服务独立密钥)
- 定期备份 + 异地
- 渗透测试

### 2.7 第三方服务故障

**风险**: Sumsub / Alchemy / SendGrid 故障。

**影响**: KYC / 链上交互 / 通知失败。

**缓解**:
- **多服务商**(KYC 用 Sumsub + Onfido 双备份)
- 多 RPC(Alchemy + Infura)
- 自托管部分通知
- SLA 监控

## 3. 业务风险(P1)

### 3.1 用户增长慢

**风险**: 6 月内用户 < 1000,产品未达 PMF。

**影响**: 资金链断裂,无法继续。

**缓解**:
- **Phase 0 调研先验证需求**
- 增加营销预算
- 调整定位(数字商品 vs 实物)
- 准备退出

### 3.2 欺诈交易

**风险**: 卖家收到款后不发货 / 买家收到假货。

**影响**: 平台仲裁成本 + 用户流失 + 声誉。

**缓解**:
- 信用分(基于历史)
- KYC 严格
- 大额交易人工审核
- 保险(后续)
- 黑名单共享

### 3.3 价格波动

**风险**: 链上 escrow 锁定 USDT,期间 ETH/USDT 汇率波动,卖家不愿收款。

**影响**: 交易卡住。

**缓解**:
- **优先 USDT**(稳定币)
- ETH 仅用于大额 / 用户主动选
- 价格锁定机制(可选)
- 超时自动释放

### 3.4 Gas 费飙升

**风险**: Ethereum L1 gas 飙升,小金额交易不经济($1 交易 gas $5)。

**影响**: 用户体验差,流失。

**缓解**:
- 推荐 L2(Arbitrum / Base)
- Gas 代付(paymaster)— 后续
- 最低交易金额限制

### 3.5 大公司进入

**风险**: eBay / Amazon / Stripe 推出类似服务。

**影响**: 流量被抢。

**缓解**:
- 早期用户社区(转换成本)
- 加密原生用户特殊功能
- 持续创新
- **避免直接竞争** — 走"加密社区专属"定位

## 4. 运营风险(P1)

### 4.1 客服压力

**风险**: 争议多,客服不足,用户不满。

**影响**: 评分低,流失。

**缓解**:
- MVP 阶段争议少(数字商品)
- 自动化客服(AI)
- 模板化回复
- 招募兼职客服

### 4.2 团队流失

**风险**: 关键工程师离开。

**影响**: 项目延期或停滞。

**缓解**:
- 关键知识文档化
- 多人在关键模块
- 股权激励
- 备份招聘渠道

### 4.3 资金不足

**风险**: 融资不顺,资金链断裂。

**影响**: 关闭。

**缓解**:
- **控制烧钱速度**(精益运营)
- 多家 VC 接触,不押注一家
- 准备应急融资 / 信贷

## 5. 法律风险(P0)

### 5.1 知识产权

**风险**: 用户发布的商品图 / 描述侵犯第三方 IP。

**影响**: 平台作为"中介"通常避风港,但有例外。

**缓解**:
- DMCA 流程(美国)
- 投诉处理流程
- 用户协议明确责任

### 5.2 用户协议可执行性

**风险**: 平台用户协议某些条款在某些辖区不可执行。

**影响**: 争议处理失败。

**缓解**:
- 律所起草,每辖区独立版本
- 定期更新

### 5.3 跨境数据传输

**风险**: 欧盟用户数据传输到美国(或其他国家),违反 GDPR。

**影响**: 罚款。

**缓解**:
- **欧盟用户数据存欧盟**(数据本地化)
- SCC(标准合同条款)
- 隐私设计

## 6. 声誉风险(P1)

### 6.1 重大事故

**风险**: 链上合约被攻击 / 数据库泄露 / 监管罚款。

**影响**: 声誉扫地。

**缓解**:
- 透明沟通
- 用户补偿
- 公开复盘

### 6.2 负面新闻

**风险**: 媒体负面报道(尤其涉及加密骗局关联)。

**影响**: 用户流失。

**缓解**:
- 公关预算
- 主动沟通
- 透明度

## 8. 应急响应计划

### 8.1 智能合约漏洞

```
发现 → 立即 Pause(多签)
  → 公告
  → 评估影响范围
  → 修复 + 升级
  → 用户补偿(如需)
  → 公开复盘
```

### 8.2 数据库泄露

```
发现 → 72 小时内通知监管(GDPR)
  → 通知受影响用户
  → 关闭漏洞
  → 内部复盘
  → 改进安全措施
```

### 8.3 监管突变

```
发现 → 法务评估
  → 准备退出方案
  → 退余额
  → 公告
  → 关闭服务(受影响辖区)
```

## 9. 不要忽略的小风险

- **GDPR 数据删除**: 用户可要求删除数据,需工程支持
- **税务**: 不同国家有不同的加密税务要求
- **货币兑换**: USDT/ETH 与法币的汇率波动影响
- **时区**: 全球用户,客服需 24/7
- **语言**: 多语言支持(至少 EN + ES + 中文)
- **文化差异**: 不同国家偏好不同(美国重隐私,东南亚重客服)
