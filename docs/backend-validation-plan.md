# 后端版本核对与数据库验证计划

更新：2026-09-09。状态：官方资料初核与实验设计完成；未安装后端依赖、未执行数据库实验，补丁版本未锁定。依据：[逻辑数据与事务](backend-data-design.md)、[ORM 评估](orm-evaluation.md)。

## 1. 版本依据与候选

| 组件 | 本轮结论 | 安装前与实验出口 |
|---|---|---|
| Node / npm | 本机实测 22.23.1 / 10.9.8；后端实验先复用该环境 | 将实际运行版本记入实验报告和 CI；不修改前端依赖 |
| NestJS / Fastify | 官方当前迁移页已是 Nest 12，不能继续把无版本文档当 Nest 11 依据；Nest 12 作为候选 | 核对 core、common、platform-fastify 的具体版本和 Fastify 依赖范围，跑启动、请求校验、错误映射与关闭连接冒烟 |
| Prisma | 采用已选 Prisma 的 v7 路线作为实验候选，使用 PostgreSQL driver adapter | 核对 CLI、Client、adapter-pg 的匹配版本与 engines；生成、编译、真实连接通过后锁定 |
| TypeScript / 模块格式 | 候选 NodeNext + ESM，独立后端 package | 核对所选 Prisma/框架的 TypeScript 下限；验证生成 Client 的导入及编译产物启动 |
| PostgreSQL | 实验建议 17 主版本，并选择执行时受支持的最新补丁 | 记录实际 server_version；部署版本与测试主版本一致，补丁更新重新走迁移冒烟 |

Nest 12 文档区分运行与脚手架的 Node 要求：22.x 运行下限为 22.12，脚手架为 22.22.3；本机满足这些文档下限，但这不证明整个依赖树兼容。[官方迁移指南](https://docs.nestjs.com/migration-guide)

Prisma v7 的连接配置和 driver adapter 需要单独处理；CLI 使用 prisma.config.ts，运行时配置 PostgreSQL adapter。安装时复核实际包要求，不能照搬旧版初始化代码。[官方 PostgreSQL 连接说明](https://www.prisma.io/docs/orm/v6/overview/databases/postgresql)、[v7 升级指南](https://docs.prisma.io/docs/orm/v6/more/upgrades/to-v7)。本次浏览工具未能读取升级指南正文，具体 engines 下限仍待包元数据核实。

PostgreSQL 官方对主版本提供五年支持；选择 17 是工程候选，不表示它是最新主版本。[官方版本政策](https://www.postgresql.org/support/versioning/)

## 2. 实验环境与执行顺序

本机检查：node --version、npm --version 成功；command -v psql、postgres、docker 均未找到工具。该结果不证明没有远程数据库；当前没有已确认的测试连接。实验不得自动使用部署库或扫描环境输出凭据。

1. 建立独立 backend 包，先核对包元数据并固定候选依赖，提交 lockfile；在报告中区分“候选安装锁定”与“验证后采用”。
2. 提供专用临时 PostgreSQL 库：本地工具或容器安装需按环境权限执行；也可使用明确提供的专用测试连接。测试入口必须显式接受测试 URL，不能回退到应用 DATABASE_URL。
3. 建立最小实验 schema，覆盖账户、商品、库存、订单与快照、reservation、问题/退款、模拟结算、事件和幂等；媒体与完整认证不阻塞数据库实验。使用虚拟身份和地址。
4. 先生成迁移再审查 SQL，补齐 CHECK、条件唯一索引与关联约束；从空库 migrate deploy。所有手写对象随迁移纳入版本库。
5. 执行下表事务用例，保留命令、版本、用例结果、最终数据库断言和失败原因；修复后重跑受影响用例。
6. 执行带数据升级与进程重启；通过后将实验模型整理为正式 schema，再进入认证和 OpenAPI 契约。

## 3. 必须通过的数据库用例

| 编号 | 编排 | 数据库验收 |
|---|---|---|
| DB-01 / T1 | 两个独立连接、不同买家与幂等键，同时购买同一实物 | 恰好一单成功；一个 active reservation；库存关联成功订单；失败方无快照、事件或幂等残片 |
| DB-02 / 幂等 | 同账户同键同内容并发；提交后模拟响应丢失，再重试 | 返回同一资源；订单、事件均只写一次；另一账户不能回放该结果 |
| DB-03 / 幂等 | 同账户同键不同内容；首事务分别提交和回滚 | 已提交时内容冲突；已回滚时后续合法请求可重新执行，无半成品结果 |
| DB-04 / T2 | 买家取消与模拟付款竞争，分别强制两种先后顺序 | 仅一种合法结果；取消则库存 available 且无付款，付款则保持原占用且不能取消 |
| DB-05 / T4 | 已付款异常订单、有交付且已有退款申请；验收与卖家退款竞争 | 最终只能 completed 或 refunded；退款仅一笔且金额/币种等于快照；库存分别 sold 或 refund_hold |
| DB-06 / T5 | 退款后恢复、重新售出，再用旧请求重复恢复 | 旧请求不能清除新订单占用；原退款与 reservation 历史保留 |
| DB-07 / 回滚 | 在占用库存、写快照、写结算、写事件后分别注入异常 | 各步骤都完全回滚，包括幂等记录；相同合法请求随后可成功 |
| DB-08 / 商品 | 下架后取消；编辑与下单竞争 | 取消不重新上架；快照来自同一商品版本，价格变动须冲突，历史快照不可被编辑覆盖 |
| DB-09 / 金额与约束 | 精确小数往返；直接写入重复 active reservation、重复结算、错商品关联 | 金额以字符串精确往返；非法写入被数据库拒绝；最终精度待币种契约，不以实验值冻结产品策略 |
| DB-10 / 迁移与持久化 | 空库迁移；插入历史样例后新增兼容字段再迁移；重启连接与应用 | 样例保留，约束仍有效；生成下一迁移不丢手写索引；重启不触发 seed 或清库 |
| DB-11 / 锁与重试 | 人工持锁触发等待超时，并模拟可重试事务错误 | 只重试整个事务且次数有上限；耗尽后无残片；唯一冲突、越权和状态冲突不盲目重试 |

并发测试须使用至少两个实际数据库连接，并通过测试屏障控制锁获取顺序；仅 Promise.all 不足以证明发生竞争。屏障设超时并在 finally 释放，避免挂起。所有用例通过新的读取连接检查提交后的状态，不能仅断言函数返回值。此实验验证数据库层，HTTP 越权、Cookie/CSRF、会话撤销和浏览器 E2E 留给对应接口工单。

## 4. 幂等实现细化

候选协议在 READ COMMITTED 事务中使用参数化 INSERT … ON CONFLICT (actorId, operation, key) DO NOTHING RETURNING，再根据是否插入区分首次执行与回放。没有插入时，用下一条 SELECT 读取已提交记录并比较 requestHash；避免在同一条语句的旧快照中假定可见。只忽略指定幂等唯一约束，其他约束错误仍应失败。[PostgreSQL INSERT 文档](https://www.postgresql.org/docs/current/sql-insert.html)

首次请求在同一事务内完成业务与结果字段，失败全部回滚；不提交没有结果的占位记录。不能普通 INSERT 抛出唯一异常后直接在已失败事务中继续 SELECT。实验期禁用幂等清理；后续若允许清理，必须另定保留与重放语义。

## 5. 紧接的交付顺序

- V1：依赖兼容核对、最小后端启动与专用数据库环境。
- V2：实验 schema、迁移 SQL、DB-01—DB-11 自动化及报告。
- C1：根据实验定稿 schema、事务封装、错误与重试映射。
- C2：认证细节、账户/商品 OpenAPI；确定币种和价格排序口径。
- C3：订单/交付 OpenAPI 与分阶段实现工单，再开始账户与商品纵向联调。

当前完成的是本计划及资料初核；V1—C3 均未验收。不将文档设计或测试清单计为实验通过。
