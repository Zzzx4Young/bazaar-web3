## 2. Phase 0: 调研 + 决策(月 0-2)

- 验证**真实用户需求**
- 决定**法律主体注册地**

### 2.2 关键动作

## 3. Phase 1: MVP 上线(月 3-6)

### 3.1 目标

- **最小可行产品上线**
- 服务**1000 个种子用户**
- 完成**1000 个真实交易**
- 验证**PMF(产品市场契合)**

### 3.2 MVP 功能范围(最小)

| 功能 | 必需 |
|---|---|
| ✅ 邮箱注册 + KYC | 必需 |
| ✅ 钱包连接(Wagmi + WalletConnect) | 必需 |
| ✅ 商品发布(图文) | 必需 |
| ✅ 商品浏览/搜索 | 必需 |
| ✅ 站内信(IM) | 必需 |
| ✅ 链上 escrow(USDT/ETH,仅 Ethereum L1) | 必需 |
| ✅ 订单状态机 | 必需 |
| ✅ 争议发起 + 平台仲裁 | 必需 |
| ⚠️ 实物二手(物流追踪) | **延后** |
| ⚠️ 多链(仅 L1) | **延后** |
| ⚠️ 拍卖 | **延后** |
| ⚠️ 商家认证 | **延后** |
| ⚠️ 信用分 | **延后** |
| ⚠️ 移动端 App | **延后**(仅 Web) |

**核心简化**: 数字商品(账号、订阅、虚拟商品)+ 数字服务(模板、代码)。**无物流,争议少**。

## 6. 关键路径(团队视角)

```
                    合约审计完成
                         ↓
                主网部署 ← 申请牌照
                    ↓
        MVP Beta ← 内部测试

            ↓
         增长
```

## 7. 不要做的事(明确)

| 不要做 | 原因 |
|---|---|
| ❌ 一次性投入所有功能 | 浪费,可能方向错 |
| ❌ 同时做 5 个国家 | 监管复杂,先 1-2 个 |
| ❌ 自建 KYC | 用 Sumsub |
| ❌ 自建物流 | 用 AfterShip |
| ❌ 自建钱包 | 用 WalletConnect |
| ❌ 不做审计就上线 | 必死 |
| ❌ 不做 KYC 就上线 | 监管风险 |
| ❌ 法币入金/出金 | 牌照太复杂 |
| ❌ 服务大陆用户 | 违法 |

## 9. 失败退出策略

**触发退出条件**:
- Phase 0 调研不达标
- Phase 1 上线 6 月后用户 < 100
- 累计 GMV < $5 万
- 监管突变(目标辖区禁止)

**退出动作**:
- 退还用户余额(链上直接退,平台不持有)
- 公开公告
- 解散团队
- **不**二次融资
- 资产清算
