更新：2026-09-13。I1—I6 已完成，当前基线为提交 `ddac854`；业务代码基线

## 目标与边界

I7 要回答三个问题：团队成员能否按交接说明独立启动环境；实物、数字商品和异常
退款流程是否可理解、可完成；失败发生时是否能用不含私有数据的证据定位到一次请求。

只使用预置账户、虚拟收件信息、测试商品和模拟结算。钱包、合约、真实支付、公开
注册、文件托管、物流接口、通知、公开部署、容量承诺、高可用和生产备份不属于 I7。
这些事项若影响内测，记录为后续决策，不在修复缺陷时顺带扩展范围。

   Cookie、CSRF、地址、链接或提取码。

## I7-1：安全诊断

接口与脱敏边界先按[请求关联与安全日志契约](backend-observability-contract.md)冻结，再修改
后端、前端、OpenAPI、CORS 和测试。

- 接受格式合法的 `X-Request-Id` 或由服务端生成不可预测 ID，并在响应头返回；CORS 和
  前端错误对象同步该契约。
- 每个完成请求只记录时间、请求 ID、方法、路由模板、状态、耗时和稳定错误码。
  未匹配 URL、查询值、body、headers 和 Prisma/驱动原始错误不进入普通日志。
- 健康检查和启动失败继续隐藏连接细节。对日志写入失败采用降级输出，不影响业务事务。
- 单元/HTTP 测试覆盖生成、透传、非法值替换、错误响应关联和敏感字段不泄漏。

## I7-2：环境与数据规则

- 使用 `postgres` 持久开发服务；`postgres-test` 只跑自动回归，停止即允许数据消失；
  `postgres-validation` 用于 DB-10 和可清理的 I7 空库重启演练，完成后停止并保留卷。
- 每轮内测使用专用数据库或明确命名的独立环境。需要完全重置时重建该可丢弃环境，
  不在共享库手工删除订单或改状态。
- 至少准备卖家、买家、外部账户三个角色。账户通过 `provision-accounts.mjs` 和权限
  `0600` 的忽略文件创建；交付后删除输入文件，凭据通过受控渠道传递。
- 测试商品和订单使用虚构内容；数字链接使用专用无敏感内容的 HTTPS 地址，不验证
  外部文件可用性。

## I7-3：人工场景清单

I7-2 本机环境演练已完成，账户凭据保存在 `backend/.tmp/i7-accounts.json`（0600、Git
忽略）。测试人员取得凭据后删除该输入文件；不得把内容复制到问题记录、日志或截图。
执行结果统一填写到[内测执行记录](internal-testing-report.md)。

1. 会话：错误密码、登录、刷新恢复、后端重启后恢复、退出失败重试和成功撤销。
2. 商品：卖家发布实物/数字商品、编辑和下架；另一账户刷新可见；外部账户不能修改。
3. 实物正常流：下单、付款、物流交付、验收；订单快照不随后续商品编辑变化。
4. 数字正常流：重复销售、付款、HTTPS 链接和提取码交付、参与方读取、验收。
5. 异常流：问题、补交、问题解决；退款申请、实物退回结果、退款和手动恢复可售。
6. 失败边界：外部账户直接读取返回 404，重复操作不产生副作用，提交后响应丢失使用
   原 payload 与幂等键重试，服务或汇率不可用时页面给出可恢复提示。

每个场景记录完成与否、理解困难、错误提示、界面显示的请求 ID 和是否需要人工查库。不得用直接
修改数据库完成业务流程。人工反馈说明可用性，不作为市场需求、容量或安全审计结论。

## 缺陷优先级与阶段出口

- **阻塞**：无法启动、登录或完成任一核心流程，数据一致性、越权或私有信息泄漏。
- **严重**：有替代步骤但会造成错误状态、结果不明无法安全重试，或关键错误无法定位。
- **一般**：不改变业务结果的文案、布局和操作理解问题。

修复顺序固定为数据/权限安全、核心流程阻塞、结果未知与恢复、诊断、可用性。任何修复
都在独立测试数据中验证，并运行受影响检查；阶段末运行完整本地与远端门禁。I7 只有在
环境可复现、场景有记录、无开放阻塞/严重缺陷且限制已交接时完成。

退出评审只提出下一阶段候选，不自动启动：继续 Alpha 可用性迭代、部署与运维验证，
或重新设计钱包/测试网交易阶段。涉及真实用户、资金或公开访问时必须另立业务、安全、
法律和部署契约。
