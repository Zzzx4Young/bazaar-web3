## 已发现并处理

| 问题 | 影响 | 处理 |
|---|---|---|
| 开发库仅部署 5/6 迁移 | 当前运行代码与 schema 不一致 | 使用迁移角色追加部署第六迁移并重授 runtime 权限 |
| 应用角色凭据未持久交接且旧临时密码失效 | 无法按 README 启动后端 | 增加受限本地恢复命令，原子轮换并生成私有 env |
| 旧后端进程占用 3001 | 当前后端默认端口无法启动 | 识别旧 PID 后 SIGTERM，当前默认端口演练通过 |
| OpenAPI 仅描述 request ID 输入 | 生成客户端无法得知响应 header | 176 个响应补齐可机读 header，并修复两个商品路由的 `id` 参数继承错误 |
| UI 丢弃 request ID | 测试人员无法直接记录失败请求 | 可见错误文本显示稳定错误码和 request ID，业务判断仍使用原错误码 |
| 凭据恢复未检查角色成员关系 | 角色可能间接继承额外权限 | 增加传递成员关系检查及目标、权限、所有权单元测试 |
| 浏览器门禁缺少数字重复销售和问题补交 | M4/M5 只有数据库证据 | 扩展真实 Chromium 门禁并完成两段界面流程 |
| 人工入口使用 `127.0.0.1` | 与后端冻结的 `localhost` Origin 不一致并返回 403 | 验收入口改用已配置 Origin 后通过；未放宽后端校验 |
